# 東京家庭旅遊 App｜V0 產品規格

## 測試旅程

- 名稱：東京家庭旅行
- 日期：2026/09/20–2026/09/26
- 主要裝置：iPhone
- 往返機場：高雄國際機場（KHH）⇄ 成田國際機場（NRT）
- 住宿：暫不處理
- 第一階段目標：讓家人從共同收藏地點，一路完成地圖判讀與每日排程。

## V0 要驗證的核心流程

建立旅程 → 加入收藏地點 → 家人表達偏好 → 在地圖查看分布 → 將鄰近地點排入同一天 → 開啟 Google Maps

第一階段不做航班、酒店管理、分帳、AI 自動排程與複雜權限。

## 六個核心畫面

1. **旅程總覽**
   - 旅行日期、參與成員、尚未安排地點、每日行程摘要
2. **地點清單**
   - 清單／地圖切換、區域與類型篩選、偏好狀態
3. **景點地圖**
   - 顯示全部候選地點、住宿候選點與指定日期行程
4. **地點詳細卡片**
   - 名稱、類型、區域、家庭偏好、留言、加入某一天、開啟 Google Maps
5. **每日行程**
   - 依日期呈現、拖曳排序、完成／跳過
6. **新增地點**
   - App 內搜尋、貼上 Google Maps 連結、解析失敗時手動建立

## 地圖互動

- 清單與地圖共用相同篩選條件。
- 點擊清單項目時，地圖定位到對應圖釘。
- 點擊圖釘時，顯示相同的地點卡片。
- 圖釘狀態：
  - 灰色：候選
  - 紫色：最想去
  - 藍色：已排入行程
  - 綠色：住宿／住宿候選
- 地圖模式：
  - **規劃地圖**：顯示所有候選地點，協助判斷區域分布。
  - **當日地圖**：顯示指定日期地點與拜訪順序。

## 家庭表態方式

- 想去
- 最想去
- 不適合我
- 無特別意見（不操作）

「不適合我」需選擇或填寫原因，例如飲食、體力、預算、時間或已去過。它屬於限制條件，不單純作為負分。

## 原型測試任務

請一位家人在沒有教學的情況下完成：

1. 查看所有收藏地點。
2. 把一間餐廳標記為「最想去」。
3. 切換到地圖，找出同區域的另一個地點。
4. 將兩個地點加入同一天。
5. 查看當日地圖。
6. 開啟其中一個地點的 Google Maps。

成功條件：不需口頭協助，且使用者知道剛才的修改會同步給其他家人。

## 功能分期建議

### 現在先做（可直接驗證規劃價值）

- 地點與旅程資料模型
- 規劃地圖／當日地圖切換
- 圖釘狀態色、推薦數與當日拜訪順序
- 依日期、景點類型及想去程度篩選
- 圖釘單一景點卡片、加入某一天與 Google Maps 跳轉
- 每日行程手動排序

### 下一階段（需要正式服務）

- Google Places 搜尋、Place ID、照片與營業資訊：需要 Google Cloud 專案、Places API、受限制的 API Key 與計費設定。
- 多人即時同步：需要帳號／旅程邀請、後端資料庫、衝突處理與離線同步。
- 住宿圖釘：住宿確定後加入真實座標；目前不放假位置。

### 後續再做（資料與複雜度較高）

- 航班與酒店管理
- 分帳
- AI 行程分析
- 複雜角色權限
- 路線自動最佳化

## 可操作原型

原型位於 `prototype/`，目前支援：

- 總覽、地點、行程三個主要頁籤
- 首次使用自行輸入匿名旅行暱稱，並以暱稱首字作為推薦標記代號
- 在收藏清單標示每個地點的新增者
- 多人各自標記「最想去」，直接顯示人數與成員名單
- 地點清單／地圖切換
- 以六個地點的真實經緯度換算地圖圖釘位置，圖釘顯示景點代號與推薦數
- 規劃地圖顯示全部候選地點；當日地圖只顯示指定日期並標示拜訪順序
- 以灰、紫、藍、綠區分候選、2 人以上推薦、已排行程及住宿
- 依日期、地點類型與想去程度篩選地圖
- 點擊單一圖釘顯示名稱、類型、區域、成員偏好、行程狀態、加入某一天及 Google Maps
- 自動展開位置接近的圖釘，避免同區景點互相遮擋
- 將同區地點加入指定日期
- 每日行程日期切換、時間修改、順序調整及景點詳情
- 收藏清單與每日行程支援左滑刪除及二次確認
- 刪除收藏會同步移除推薦與相關行程；刪除行程只影響當天安排
- 地點詳情的介紹、重點標籤、票選狀態與照片版位預覽
- 新增自訂地點
- 開啟原始 Google Maps 連結
- 以瀏覽器本機儲存保留暱稱、個人票選、行程與自訂地點

在 `travel-app` 的上一層目錄執行：

```powershell
python -m http.server 4173 -d travel-app
```

然後開啟：

`http://127.0.0.1:4173/prototype/`

此版本是無後端的互動驗證原型。地圖依真實座標以相同比例投影，但道路底圖仍是示意圖，並非正式導航地圖；導航由原始 Google Maps 連結負責。

地點詳情目前使用明確標示的照片版位預覽，不冒充 Google Maps 使用者照片。正式串接時應以 Places API 的 Place Photos 取得照片，保留必要的作者標示與 Google Maps 來源連結，且不快取照片資源名稱。
