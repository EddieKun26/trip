## Selection-first Place Pool (AI Planner Phase 1B.0) — review gate, 2026-09-16

- Reason for this round: Phase 1A shipped a manual add-to-day flow, but production UX review rejected forcing the user to pick a day for every Place one at a time. New primary flow: tap Places to build a "確定想去" set, then a sticky CTA hands that set to the (not-yet-built) AI Planner, which owns date/area/order.
- Worktree `travel-app/prototype/selection-first-place-pool`, branch `feat/selection-first-place-pool`, baseline `origin/main` 06a1f6ede967e9a8730a494193d0ff177f49bd84 (fetched and verified, exact match). Uncommitted; awaiting review. No commit, push or deploy.
- `aiCandidateSelection`/`aiCandidatePlaceKeys`/`placePoolCandidateEntries` are renamed to `placePoolSelection`/`placePoolSelectedKeys`/`placePoolSelectedEntries` and their semantics flipped: selected is now HARD (the AI Planner must schedule it exactly once), not "candidate-only". Still trip-scoped in-memory `placeDetailKey` keys on `state.tripId`, never persisted/stored/sent; `placePoolSelectedEntries()` also lazily prunes any key whose Place left the pool (scheduled elsewhere, deleted, or turned same-name ambiguous), so the displayed count is always "currently valid entries", never the raw `Set.size`.
- Card click semantics inverted: tapping/clicking the card body now toggles selection (`aria-pressed`) instead of opening the add-a-day sheet. The old manual-add path is now a secondary action: a sibling `[data-pool-add]` button (＋日期 docked / ⋯ touch) still opens the unchanged `openPlacePoolAddSheet` → `addPlaceToItineraryDay` → `insertPlacesIntoItineraryDay` → `persist()` chain. Desktop drag moved to a dedicated sibling handle (`[data-pool-drag]`, ⠿, docked-only, `aria-label`); the selectable card surface is never `draggable`, so click-to-select and native drag can never race on the same element.
- Rendering: `placePoolViewModel()` splits `getFilteredPlacePool()`'s entries into an always-visible Selected section (built from the unfiltered pool, so a selected Place stays visible with a "不在目前篩選" note when it stops matching 主要地區/地點類型/最想去) and a filtered 其他地點 section. Both preserve `getUnscheduledPlaces()`'s stable order regardless of selection/click order; unselecting returns a card to that same position. Past 6 selected entries the section collapses behind one `已選 N 個 ▾` toggle (`state.placePool.selectedExpanded`) so a long selection cannot bury the rest of the pool, especially on mobile.
- Sticky CTA (`[data-pool-cta]`) reads "AI 幫我規劃行程" at 0 selected or "用已選 N 個地點規劃" above 0, with an "AI 規劃準備中" hint. It ships `disabled`/`aria-disabled` and has no click handler at all: 0 network, 0 persist, 0 itinerary mutation in this round. No OpenAI/AI Planner call was added anywhere.
