# Known issues

- Booking.com now answers server-side page fetches with an HTTP 202 anti-bot challenge page (observed 2026-08-21), so no public title, Open Graph, or structured address reaches the importer from a bare Booking link. Recognition then depends on the AI web search guided by the URL slug and dest_id; results are best-effort. The reliable path is pasting the host-provided lodging name and address (e.g. `公寓名稱：… / 公寓地址：…`) together with the Booking link, which now deterministically produces a correctly named precise coordinate candidate without needing the page.
- The Google Maps key was previously shared in conversation. It should be rotated and restricted in Google Cloud before broader public use.
- Google Maps browser-map availability depends on correct production referrer restrictions; Leaflet is the fallback when the key cannot load.
- Google Maps shared-list import works only for publicly accessible lists. Private lists cannot be expanded server-side.
- Instagram and Threads may block server-side public metadata or require login. Publicly exposed main-post carousel images are now recognized automatically, including Threads image attachments after a video cover, but inaccessible/private media, full video frames, and replies may still require screenshots containing the names.
- WebKit does not currently implement the Web Share Target manifest member (WebKit bug 194593 remains open as of 2026-08-27). The App's tested `/share-target` receiver can register on compatible installed-PWA platforms, but it cannot appear in the iPhone system share sheet. iPhone users must keep using paste/screenshot import unless an iOS Shortcut or native Share Extension is shipped; Web Share support for sending content does not imply Web Share Target support for receiving it.
- Source-comparison images use the public Meta attachment URLs available during recognition. A platform may later expire or block one of those URLs; the comparison sheet therefore retains an `開啟完整原貼文` fallback, while user-uploaded screenshots remain available for the current pending import session.
- Social posts can return up to twenty place groups, but practical completeness still depends on the post exposing readable names, addresses, or screenshots and on Google Places finding each mention. Candidate searches are concurrency-limited, so unusually long lists may take longer than short posts.
- A targeted social-place rematch searches Google Maps rather than rerunning visual AI. When the source image contains an unreadable or incomplete shop name, the user may still need to correct the store name, branch, or address manually before a match appears; the group can always be skipped.
- Instagram profile/pinned external links are not reliably exposed in public metadata. A caption-level address can still produce Google lodging candidates, but a broad neighborhood-only address may match several plausible properties and always requires the user's explicit selection.
- The local airport catalog is intentionally curated rather than exhaustive; unsupported cities need catalog additions.
- Multi-leg creation supports up to six legs per direction and includes common Europe, Middle East, and North America hubs, but an unsupported transfer airport still needs a catalog addition before selection.
- Browser-based ticket OCR is optimized for airport codes, English month names, dates, and colon-formatted times. Low-resolution, handwritten, or heavily stylized tickets may need manual correction.
- First-time ticket OCR requires an internet connection to download the browser recognition worker and English language data; later loads may use the browser cache.
- Shopping screenshot recognition depends on a separately billed OpenAI API project and a Vercel server-side `OPENAI_API_KEY`; ChatGPT Plus quota does not supply API usage. Dense or unclear posters can still have low-confidence results, so every recognized field remains editable and requires confirmation.
- Shopping price recognition intentionally leaves bundle promotions, crossed-out prices, tax ambiguity, or prices not clearly tied to the main item blank. Currency totals are estimates and are not converted across exchange rates.
- Shopping image candidates depend on matching public official or retail pages exposing usable product metadata. Some sites block server fetches, publish oversized images, omit Product/og:image metadata, or expose only advertising art. The App now automatically runs two alternative searches when the primary result is incomplete, but fewer than three candidates can still appear when every matching source is inaccessible; users may then use `換一批圖片` or save without a product image.
- Web product photos and regional packaging can differ from the uploaded recommendation screenshot. Candidate selection is always explicit; users must verify the package, model, capacity, and color before saving or purchasing.
- A twelve-image import can create up to twelve concurrent OpenAI recognition requests. Individual cards may still report rate-limit or temporary network failures independently; successful cards remain editable and failed cards can be retried in a later selection. iOS's native web photo picker does not expose a maximum-selection control, so the App can only reject an over-twelve selection after the picker closes.
- Private shopping screenshots and manually selected product images are higher-resolution compressed reference images stored in Redis for the web prototype. Each member/trip can retain up to 16 images but the total payload ceiling may prune older photos sooner; item text remains. Photos uploaded before the 2026-08-09 quality upgrade cannot be reconstructed and must be re-uploaded to become clear.
- Walking time is currently estimated from the two saved coordinates with a walking-route factor. It is not live Google routing and may need manual adjustment for barriers, station interiors, or inaccessible paths.
- Shared production data depends on Vercel/Upstash availability. Device-local state is not a substitute for the shared store.
- A browser tab that was already running code from before the 2026-08-11 deployment-version check must be refreshed or reopened once. After it loads the protected build, future deployments are detected when the tab returns to the foreground.
